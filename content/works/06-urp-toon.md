Maze의 캐릭터에 셀 애니메이션 느낌의 툰 룩을 입히기 위해 만든 URP 툰 셰이더입니다. 툰 셰이딩의 기본 원리는 앞서 DirectX 11로 직접 구현하며 정리한 적이 있습니다. 이 케이스는 그 원리를 다시 설명하기보다, 같은 룩을 상용 엔진(Unity URP)의 정해진 파이프라인 위에서 모바일 예산에 맞춰 어떻게 구현했는지를 다룹니다.

![캐릭터에 적용한 URP 툰 셰이더.](assets/works/mob-toon.png)

시작은 세 가지 제약이었습니다.

- 타깃이 **안드로이드 모바일, 2160×1440, 60fps**. 라이팅에 쓸 예산이 거의 없습니다.
- 아트팀이 그림자의 **'색'을 직접 칠하고** 싶어 합니다. 단순히 어둡게가 아니라 "그림자는 보라색으로".
- 캐릭터는 **환경이 아무리 어두워도 항상 잘 보여야** 합니다. 게임의 주인공이기 때문입니다.

이 세 조건이 셰이더의 모든 설계 결정을 만들었습니다. 아래는 각 조건이 어떤 결정으로 이어졌는지 순서대로 정리한 것입니다.

## 1. 라이팅을 미룬다 — 디퍼드 리졸브로 픽셀당 한 번

Maze는 그래픽 프로그래머가 구축한 **커스텀 디퍼드 렌더러**를 씁니다. 제 툰 셰이딩은 그 파이프라인 위에 얹혔고, 그래서 셰이더도 그 구조에 맞춰 짜야 했습니다. 핵심은 **캐릭터 셰이더가 색을 직접 계산하지 않는다**는 점입니다. 일이 두 단계로 나뉩니다.

- **캐릭터 패스** — 이 픽셀의 베이스색, 그림자색, 경계 위치 같은 '재료 정보'만 지-버퍼(GBuffer)에 적고 끝냅니다. 빛 계산은 하지 않습니다.
- **풀스크린 리졸브** — 화면을 딱 한 번 훑으며, 그제야 재료와 빛을 섞어 최종 색을 만듭니다. 제가 짠 셀 셰이딩 로직(뒤에 나올 밴드·세 톤·캐릭터 조명)은 이 리졸브 단계에서 계산됩니다.

이 구조는 모바일에서 가장 부담이 큰 오버드로우에 강합니다. 캐릭터가 반투명 이펙트나 다른 캐릭터와 겹쳐 그려져도, 조명 계산이 리졸브로 미뤄져 있어 **화면 픽셀당 조명은 단 한 번**입니다. 셰이더가 직접 라이팅하면 겹친 횟수만큼 반복될 무거운 계산이, 픽셀당 1회로 묶이는 셈입니다. 그래서 저는 셀 셰이딩을 이 리졸브 안에서, 분기 없이 마스크 곱과 half 정밀도로 가볍게 얹는 데 집중했습니다.

![캐릭터 패스는 재료만 기록하고, 조명은 풀스크린 리졸브에서 픽셀당 한 번만 계산합니다.](img/06-urp-toon/fig02-deferred-flow.png)

이 디퍼드 구조에는 **대가**도 있습니다. 재료 버퍼 여러 장을 메모리에 썼다가 리졸브에서 다시 읽어야 해서, 타일 기반 모바일 GPU에서는 그 왕복이 **적잖은 대역폭**을 씁니다.

이건 제가 설계한 부분은 아니지만, 제 셰이딩이 그 위에서 도는 만큼 왜 이렇게 되어 있는지는 이해하고 작업했습니다.

**대역폭을 감수하고 버퍼를 상주시키는 건 렌더러 차원의 선택입니다.** 바닥 데칼·아웃라인 포스트프로세스·포그·오클루전·물처럼 여러 패스가 같은 노멀·포지션·재료 버퍼를 공유해야 하기 때문입니다.

## 2. 그라데이션 대신 밴드 — 경계를 아트팀 손잡이로

셰이딩 모델 자체는 밴드(band) 방식입니다. 일반 램버트는 빛과 노말의 내적(N·L)이 0.30, 0.31, 0.32…처럼 연속으로 이어지는데, 툰 룩은 이 명암을 계단처럼 잘라야 합니다.

자르는 도구는 하나입니다. `InverseLerp`에 `saturate`를 씌운 경계 함수로, `[min, max]` 구간 밖은 0 또는 1로 딱 잘리고 안에서만 부드럽게 이어집니다. 즉 **경계선 하나**를 만듭니다.

다만 아트팀에게 min/max를 그대로 주지 않고, 더 직관적인 두 개의 손잡이로 바꿔 노출했습니다.

- **경계 위치(Step)** — 밝음과 그림자가 갈리는 지점
- **경계 폭(Feather)** — 경계의 부드러움 (0이면 칼같은 애니 라인, 크면 부드러운 그라데이션)

```
[min, max] = [Step - Feather/2,  Step + Feather/2]
```

이 두 손잡이만으로 "쨍한 셀 룩"과 "부드러운 지브리풍"을 같은 셰이더에서 오갈 수 있습니다. 코드를 건드리지 않고 아티스트가 룩을 조율하게 한 것이 두 번째 결정입니다.

## 3. 밴드 둘, 색 셋 — 그림자를 곱하지 않고 칠한다

경계 함수를 **두 번** 쓰면 화면이 세 구역으로 나뉩니다. 하나는 밝음과 그림자를 가르고, 다른 하나는 그림자를 다시 얕은 그림자와 깊은 그림자로 가릅니다.

```
N·L 큼 ───────────────────────────▶ N·L 작음
[  밝은 톤  |  중간 그림자  |  깊은 그림자  ]
```

핵심은 여기입니다. **그림자를 "어둡게 곱하기"로 만들지 않았습니다.** 밝은 톤, 중간 그림자, 깊은 그림자가 전부 **독립된 색**이고, 세 구역의 가중치에 각각의 색을 곱해 더합니다. 그래서 아트팀이 "그림자는 차갑게 파랑, 깊은 그림자는 보라"처럼 자유롭게 채색할 수 있습니다. 애니메이션 셀화 느낌의 핵심이 이 세 개의 독립 색입니다.

깊은 그림자(세 번째 톤)는 예산을 아끼려 **캐릭터에만** 켭니다. 환경 오브젝트는 두 톤으로 충분하기 때문입니다.

![세 구역에 각각 독립된 색을 입혀, 그림자를 어둡게가 아니라 다른 색으로 칠한 결과.](img/06-urp-toon/fig04-three-tones.png)

## 4. 캐릭터는 세상과 다른 빛을 받는다 — 전용 키라이트 리그

마지막 조건은 "캐릭터는 항상 잘 보여야 한다"였습니다. 그래서 리졸브 단계에서 픽셀이 **캐릭터인지 환경인지** 구분하고, 캐릭터라면 조명을 통째로 갈아끼웁니다.

- 빛 방향을 살짝 위로 들어 올려, 얼굴에 항상 보기 좋은 명암이 지게 합니다.
- 환경의 태양색을 무시하고, 코드가 매 프레임 주입하는 **캐릭터 전용 키라이트 색**을 씁니다.
- 그림자 감쇠를 강제로 무효화해, 캐릭터가 다른 물체의 그림자에 파묻히지 않게 합니다.

정리하면 캐릭터에게는 **개인 조명 스태프가 따라다니는** 셈입니다. 무대(환경)가 아무리 어두워도 배우(캐릭터)의 얼굴엔 항상 조명이 떨어지도록, 환경 태양광과 캐릭터 키라이트를 완전히 분리해 둔 것이 이를 가능하게 합니다.

![환경이 어두워도 캐릭터에만 전용 키라이트가 떨어져 실루엣과 명암이 유지되는 모습.](img/06-urp-toon/fig05-character-rig.png)

## 셀 셰이딩 — 정리

세 가지 제약이 세 가지 설계 결정으로 그대로 이어졌습니다.

- **모바일 성능** → 라이팅이 픽셀당 1회로 처리되는 디퍼드 구조에 맞춰, 셀 셰이딩을 half 정밀도·분기 없는 마스크 곱으로 가볍게 얹음
- **아트팀이 그림자를 칠하고 싶다** → 세 개의 독립 색 + 경계 위치·폭 두 손잡이
- **캐릭터는 항상 잘 보인다** → 환경과 분리된 전용 키라이트 리그

한 줄로 요약하면, N·L을 두 경계로 잘라 세 개의 밴드를 만들고 각 밴드에 아트팀이 칠한 색을 입히되, 무거운 계산은 디퍼드 리졸브에 맡기고 캐릭터만큼은 환경과 다른 개인 조명을 받게 한 셀 셰이더입니다.

## 외곽선에 대한 여러 가지 방법

여기까지가 툰의 절반인 명암이었습니다. 남은 절반은 외곽선입니다. 만화·애니 룩에서 외곽선은 생명이지만, 3D에서 선을 긋는 일은 생각보다 까다롭습니다. 선에는 성격이 정반대인 두 종류가 있기 때문입니다.

- **실루엣 선(바깥 윤곽)** — 캐릭터와 배경이 만나는 경계. 몸 전체를 감싸는 테두리.
- **내부 선(안쪽 디테일)** — 옷 주름, 얼굴 굴곡, 손가락 사이처럼 실루엣 안쪽에서 형태가 접히는 선.

실루엣은 "모양을 바깥으로 키워서" 만들고, 내부 선은 "화면을 분석해 꺾이는 곳을 찾아서" 만듭니다. 한 기법으로 둘 다 잘하기 어려워, 서로 잘하는 것이 다른 세 기법이 역할을 나눠 그립니다. 여기에도 같은 제약이 붙었습니다.

- 모바일 예산
- 아트팀이 부위별로 두께를 조절하고 싶다는 요구

## 1. 바깥 실루엣 — 배면법(Inverted Hull)

가장 기본이 되는 바깥 테두리부터입니다. 원리는 단순합니다. 캐릭터를 아주 조금 크게 복제한 껍데기를 씌우고, 그 껍데기의 **앞면은 버리고 뒷면만** 그립니다. 그러면 원본 실루엣 바로 바깥으로 삐져나온 부분만 테두리로 남습니다.

```
확장위치 = 원래위치 + 스무스법선 × 두께   // 껍데기를 법선 방향으로 부풀림
// 렌더 패스: 앞면을 버리고 뒷면만 그림(Cull Front) → "배면법"의 유래
```

핵심 디테일은 둘입니다.

- **스무스 법선을 쓴다.** 일반 메시 법선으로 부풀리면 딱딱한 모서리(하드 엣지)에서 껍데기가 찢어져 테두리가 끊깁니다. 그래서 이웃 면들의 평균 법선을 미리 구워 두고, 그 매끈한 법선 방향으로 부풀립니다. 그래야 테두리가 갈라지지 않습니다.
- **두께를 정점 가중치로 조절한다.** 두께를 아주 좁은 범위로 제한한 뒤, 각 정점에 아티스트가 칠한 부위별 가중치를 곱합니다. 눈가는 얇게, 실루엣은 굵게 같은 미세 조정이 됩니다. 또 테두리가 원본과 겹치지 않도록 깊이를 살짝 밀어 둡니다.

장점은 **메시당 드로우콜 한 번**이라 모바일 친화적이라는 점이고, 약점은 바로 다음에서 드러납니다.

![일반 메시 법선(왼쪽)은 하드 엣지에서 껍데기가 찢어지고, 이웃 면 평균을 구운 스무스 법선(오른쪽)은 테두리가 끊기지 않습니다.](img/06-urp-toon/fig06-smooth-normal.png)

## 2. 얇고 굽은 부위 보강 — 8방향 스크린 푸시

배면법은 대부분 잘 되지만, 손가락처럼 얇거나 링처럼 뚫린 부위, 메시가 분리된 곳에서는 스무스 법선이 껍데기를 제대로 닫지 못해 **테두리에 틈이 생깁니다.** 그래서 오래전부터 쓰던 방법을 보강용으로 함께 켭니다. 정점을 화면 공간에서 사방으로 조금씩 밀어 여러 번 그리고, 겹쳐 쌓인 것이 테두리가 되는 방식입니다.

```
방향[i] = (cos(2πi/N), sin(2πi/N))   // 화면에서 원형으로 균등 분포한 방향
정점을 방향[i]만큼 밀어 N번 그림 → 겹쳐 쌓여 테두리
```

법선이 아니라 **화면 공간의 고정 방향**으로 밀기 때문에, 메시 모양이 어떻든 사방으로 균일하게 부풀어 얇고 굽은 부위의 틈을 잘 메웁니다. 트레이드오프는 방향 수 N만큼 드로우콜이 곱해진다는 것입니다(모바일에서 5방향이면 메시당 5번). 그래서 이건 메인이 아니라 **배면법이 약한 곳을 메우는 보조**로, 머티리얼 토글로 필요한 메시에만 켭니다.

덧붙이면, 배면법과 8방향을 코드가 부위별로 강제 분리한 것은 아닙니다. 둘 다 실루엣을 확장하는 기법이고, 두 개의 토글로 아티스트가 메시·부위별로 조합합니다. 분업은 코드가 아니라 운용 규칙입니다.

## 3. 안쪽 주름선 — 노멀 기반 포스트프로세스

세 번째는 성격이 완전히 다릅니다. 실루엣이 아니라 캐릭터 **안쪽**의 선 — 옷 주름, 얼굴 굴곡, 관절 접힘 같은 것입니다. 이건 메시를 부풀려서는 만들 수 없습니다. 대신 화면을 다 그린 뒤, 그 결과 화면을 분석합니다. 방법은 이미지 처리에서 윤곽을 딸 때 쓰는 **Sobel 엣지 검출**인데, 색이 아니라 **노멀(법선) 버퍼**를 분석합니다.

```
엣지     = Sobel(노멀버퍼)                // 이웃 픽셀의 노멀 차이
선       = step(민감도, 엣지)             // 임계값을 넘으면 선(1)
거리페이드 = 1 - smoothstep(near, far, 깊이)  // 멀면 선이 사라짐
결과     = 원본색 × (선 위치를 어둡게)      // 곱셈 블렌드
```

한 줄로, 옆 픽셀과 **법선 방향이 급격히 꺾이는 곳** = 형태가 접히는 곳 = 내부 선입니다. 거기를 어둡게 칠합니다. 디테일은 넷입니다.

- **깊이가 아니라 노멀 기반.** 깊이는 "얼마나 멀리 떨어졌나"라 실루엣을 잡고, 노멀은 "얼마나 꺾였나"라 내부 주름을 잡습니다. 그래서 내부선에는 노멀을 씁니다.
- **곱셈 블렌드.** 새 색을 얹는 게 아니라 원본 화면을 어둡게 만들어 선을 냅니다.
- **캐릭터에만 적용.** 불투명 렌더에서 캐릭터에만 스텐실을 찍어 두고, 포스트프로세스는 그 픽셀에서만 계산합니다. 화면 전체를 훑되 배경에는 내부선을 그리지 않고, 불필요한 계산도 줄입니다.
- **거리 페이드.** 카메라에서 멀어지면 내부선이 스르륵 사라집니다. 멀리 있는 캐릭터에 잔선이 지글대는 것을 막습니다.

## 4. 세 기법을 파이프라인에 얹기

세 기법은 각각 URP의 렌더러 피처로 파이프라인에 등록됩니다.

- **배면법·8방향**은 메시를 다시 그리는 방식이라 캐릭터 지오메트리가 필요합니다. 그래서 불투명 렌더 직후에 실행합니다.
- **포스트프로세스**는 이미 그려진 화면을 후처리하는 방식이라, 깊이·노멀 버퍼가 준비된 뒤 풀스크린으로 한 번 돕니다.

세 피처 모두 두께·민감도·페이드 같은 파라미터를 인스펙터에 노출해, 아트팀이 코드 없이 조절할 수 있게 했습니다.

## 외곽선 — 정리

명암과 마찬가지로, 외곽선도 조건이 그대로 설계가 됐습니다.

- **선에는 두 종류(실루엣·내부)가 있다** → 기법을 바깥용(배면법·8방향)과 안쪽용(포스트프로세스)으로 분리
- **모바일 성능** → 메인은 1 드로우콜짜리 배면법, 무거운 8방향은 필요할 때만 토글, 포스트프로세스는 캐릭터 픽셀로 한정
- **아트팀 제어** → 부위별 두께(정점 가중치)·패스 토글·피처 파라미터로 코드 없이 조율

한 줄로 요약하면, 바깥 실루엣은 값싼 배면법으로 그리고, 배면법이 약한 얇은 부위는 8방향 스크린 푸시로 메우며, 실루엣이 못 잡는 안쪽 주름선은 노멀 기반 포스트프로세스로 따로 그리는 3분업 외곽선 시스템입니다.

Maze에서 캐릭터가 회피할 때 뒤에 남는 파란 잔상, 즉 모션 트레일입니다.

![회피 잔상 시연. 회피 순간 캐릭터 뒤로 파란 잔상이 남았다가 사라집니다.](img/09-motion-trail/Motion.mp4){w=420}

- **잔상이 진짜 캐릭터 실루엣이어야 했습니다.** 팔다리를 벌린 회피 포즈 그대로 남아야 합니다.
- **모바일에서 가벼워야 했습니다.** 안드로이드 타깃인데 잔상은 매 순간 캐릭터를 통째로 복제하는 작업입니다.
- **안 쓸 때는 비용이 0이어야 했습니다.** 회피는 가끔 쓰는 동작이라 발동하지 않는 대부분의 시간에는 계산이 전혀 없어야 합니다.

## 1. BakeMesh로 캐릭터 포즈를 정적 메시로 굽기

가장 먼저 정한 것은 **잔상을 파티클로 흉내내지 않고 그 순간의 캐릭터 메시를 통째로 굽는다**는 것입니다. 그래서 스키닝이 끝난 현재 포즈의 메시를 그대로 정적 메시로 떠내는 `SkinnedMeshRenderer.BakeMesh`를 썼습니다.

```
회피하는 그 프레임의 캐릭터
   SkinnedMeshRenderer  ──BakeMesh──▶  정적 Mesh 스냅샷 (그 포즈 그대로 박제)
                                          └─ 월드 위치·회전·스케일 다시 입혀 실물과 정확히 겹침
```

- 스키닝된 실제 실루엣이라 회피 포즈든 공격 포즈든 **캐릭터 그 자체**가 잔상으로 남습니다.
- 애니메이션 뼈를 따라가는 게 아니라 **그 순간을 박제**한 것이라 원본이 계속 움직여도 잔상은 그 자리에 멈춰 있습니다. 그래서 "지나온 궤적"이 보입니다.

진짜 실루엣이어야 이물감이 없다는 것이 이 시스템의 첫 번째 원칙, **"흉내내지 말고 박제한다"** 입니다.

## 2. 라이팅 없는 Additive 단색으로 그리기

박제한 메시를 그릴 때 최적화를 위해 잔상은 **라이팅을 계산하지 않는 Additive 단색**으로만 그렸습니다.

```
고스트 머티리얼
   라이팅        계산 안 함 (Unlit)
   그림자        안 드리움 / 안 받음
   라이트프로브   끔
   리플렉션프로브  끔
   블렌딩        Additive — 겹칠수록 밝게 더해짐
```

- 잔상은 장식이라 라이팅·그림자를 계산하는 것은 낭비입니다. 전부 껐습니다.
- **Additive**라 잔상이 서로 겹치는 몸통 부분이 자연스럽게 더 밝아집니다. 속도감이 살아납니다.

## 3. 고스트 슬롯을 미리 만들어 두고 돌려쓰기

마지막 조건은 모바일에서 가벼워야 하고 안 쓸 때는 비용이 0이어야 한다는 것이었습니다. 그래서 이미터가 게임 시작 때 필요한 것을 전부 미리 만들어 놓고, 회피 때는 **아무것도 새로 만들지 않게** 했습니다.

```
[BuildPool — 게임 시작 시 1회]
   고스트 슬롯 N개(기본 4) 미리 생성
   각 슬롯에 빈 Mesh(MarkDynamic) 준비
   전 슬롯을 사전 BakeMesh 1회  ← GPU 버퍼 할당 (렌더는 안 함)
   머티리얼 배열도 여기서 한 번만 세팅
        │
        ▼
[Emit — 회피 중, 간격마다]
   빈 슬롯 재사용 (없으면 가장 오래된 것 뺏음)
   그 슬롯의 Mesh에 다시 구움 → 새 할당 0
```

- **런타임 할당 제로** — 회피 도중 `new`도 `Instantiate`도 없어 GC 스파이크가 없습니다.
- **첫 발동 히치 제거** — 사전 BakeMesh로 GPU 버퍼를 미리 잡아 둬서 첫 회피가 뚝 끊기지 않습니다.
- **평상시 0 비용** — 회피를 안 쓰면 `LateUpdate`가 그냥 통과합니다. 켜진 잔상이 없으면 계산할 것이 없습니다.

특별한 기법을 쓴 것은 아니고 필요한 것을 미리 만들어 두고 돌려쓰게 한 것입니다.

## 4. LateUpdate에서 방출하고 페이드하기

방출과 페이드는 전부 **`LateUpdate`** 에서 일어납니다. 하필 LateUpdate인 이유는 **애니메이션 평가가 끝난 뒤**라 그 프레임의 캐릭터 포즈가 이미 확정돼 있기 때문입니다. 여기서 구워야 정확한 실루엣이 나옵니다.

```
회피 스킬이 Play(duration) 호출
   → _emitUntil = 지금 + duration   (언제까지 뿌릴지)
   → _nextEmit  = 지금              (즉시 첫 장)
```

`_interval`이 잔상 사이 간격(촘촘함)을, `_fade`가 한 장이 사라지는 데 걸리는 시간(꼬리 길이)을 정합니다. 이 둘로 "촘촘하고 짧은 잔상"부터 "듬성듬성하고 긴 꼬리"까지 조율합니다.

## 5. 전체 흐름

```
[회피 스킬 발동]
   후방 변위 + 무적(i-frame) 플래시 + 잔상  ← 회피 손맛 3종
   트레일 지속시간 > 0 이면 → Afterimage.Play(지속시간)
        │
        ▼
[이미터 — 이미 BuildPool로 만들어 놓은 상태]
   LateUpdate ① 방출: _interval 마다
        빈 고스트 슬롯 재사용 → 현재 포즈를 BakeMesh로 박제
        월드 위치·회전 + lossyScale 재적용 (실물과 정확히 겹침)
        │
        ▼
   LateUpdate ② 페이드: 고스트마다
        밝기 = (1 - t) × 색.a  →  Additive라 rgb에 곱해 어두워지며 소멸
        수명이 다한 슬롯은 풀로 반납
        │
        ▼
[회피 끝 → 방출 멈춤 → 남은 잔상 페이드 후 전부 반납 → 다시 0 비용]
```

## 정리

한 줄로 요약하면 회피하는 그 순간의 캐릭터 메시를 통째로 구워 정적 실루엣으로 박제하고, 빛 계산 없는 Additive 단색으로 밝기만 줄여 지우되, 전부 미리 만들어 놓은 풀로 돌려써서 모바일에서도 회피할 때만 켜지는 가벼운 잔상 시스템입니다.
